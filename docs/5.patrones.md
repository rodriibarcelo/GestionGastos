# 5. Patrones de diseño usados

El enunciado exige (mínimo): **Estrategia** (alertas) + **Adaptador** y **Método Factoría** (importador), y **Singleton** donde proceda. Además, se aplica **Repositorio** para persistencia.

---

## 5.1. Strategy (Estrategia) — Alertas

**Problema a resolver:** existen distintos tipos de alerta (por ejemplo, por total diario, por importe mayor, etc.) y queremos evaluarlas sin condicionales grandes.

**Solución planteada:** una interfaz común `AlertaStrategy` y varias implementaciones concretas.  
`GestorAlertas` compone una lista de estrategias y las aplica para generar mensajes.

- **Interfaz:** `gestiongastos.alertas.AlertaStrategy`
- **Estrategias concretas:** `AlertaTotalDiario`, `AlertaImporteMayor`, (etc.)
- **Contexto:** `GestorAlertas`

Ventaja: si queremos añadir una nueva alerta es crear una nueva clase que implemente la interfaz, sin tocar el resto del sistema.

---

## 5.2. Adapter (Adaptador) — Importación de gastos

**Problema a resolver:** los ficheros externos (p.ej., exportación bancaria) tienen un formato distinto al modelo del sistema.

**Solución planteada:** `ImportadorGastos` actúa como **interfaz destino** (Target) y `ImportadorCSV` adapta el formato CSV externo para producir `List<Gasto>` del dominio.

- **Target:** `gestiongastos.importador.ImportadorGastos`
- **Adapter:** `gestiongastos.importador.ImportadorCSV`

Ventaja: se pueden crear más adaptadores (por ejemplo `ImportadorXLS`, `ImportadorBancoY`) sin cambiar la lógica de importación en la aplicación.

---

## 5.3. Factory Method — Selección de importador

**Problema a resolver:** elegir el importador adecuado según el tipo de fichero sin acoplar la UI a clases concretas.

**Solución planteada:** `ImportadorFactory.crear(tipo)` devuelve una instancia de `ImportadorGastos` según una clave (p.ej. `"csv"`).

- **Factoria:** `gestiongastos.importador.ImportadorFactory`

Ventaja: la selección queda centralizada y el sistema es extensible.

---

## 5.4. Singleton — Acceso global al controlador

**Problema a resolver:** hay un único controlador que mantiene el estado de sesión (usuario actual) y coordina el acceso a servicios.

**Solución planteada:** `Controlador` expone una única instancia global mediante `getInstance()`.

- **Singleton:** `gestiongastos.controlador.Controlador`

---

## 5.5. Repository — Desacoplo de persistencia

**Problema a resolver:** evitar que la lógica de negocio dependa del detalle de almacenamiento (JSON/Jackson).

**Solución planteada:** interfaces de repositorio (`GastoRepository`, `CategoriaRepository`, etc.) y una implementación concreta en JSON (`*RepositoryJson`).

Ejemplos:
- `GastoRepository` + `GastoRepositoryJson`
- `UsuarioRepository` + `UsuarioRepositoryJson`
- `NotificacionRepository` + `NotificacionRepositoryJson`

Ventaja: permite sustituir JSON por otra persistencia (p.ej. BD) sin reescribir servicios.
